# Remote LXC & SSHFS Multi-Host Workflow Guide

This guide establishes exact operational procedures, path mappings, Git synchronization rules, and Podman Quadlet deployment practices for **MoneyMakingMachine (`trader-core`)** when developing from an Arch Linux laptop (**`lgram`**) and executing on a production LXC container (**`trader`**).

---

## 1. System Topology & Environment Mapping

| Attribute | Developer Client (`lgram`) | Execution Container (`trader`) |
| :--- | :--- | :--- |
| **System Role** | Development workstation, code editor, agent runtime | Production execution host, Podman engine, event loop |
| **Operating System** | Arch Linux (Laptop) | Linux LXC Container |
| **Repository Path** | `/home/vineet/mnt/trader-core` (or SSHFS mount) | `~/trader-core` (`/home/vineet/trader-core`) |
| **Shell Prompt** | `[vineet@LGRAM ~]$` or `vineet@LGRAM ~/mnt/trader-core $` | `[vineet@trader ~]$` |
| **Python Virtualenv** | `./.venv/bin/python` | `./.venv/bin/python` |
| **LAN Access** | Client-side sandbox | Direct bridge to `10.10.10.15:11434` & `192.168.2.15:8080` |
| **Persistent Storage** | Host filesystem mount | `/var/lib/trader-core/data` & `/etc/trader-core/.env` |

---

## 2. Invariants & Rules of Engagement

### A. Path Separation Invariant
* **NEVER** instruct the user on `trader` (`[vineet@trader ~]$`) to run commands containing laptop mount paths (such as `cd ~/mnt/trader-core` or `./deploy/...` without navigating to the repo first).
* Commands meant for execution on `trader` must always explicitly target:
  ```bash
  cd ~/trader-core
  ```

### B. Git Push/Pull Synchronization Invariant
* Files edited or generated by Antigravity on `lgram` live in the laptop's working copy.
* `trader` is a separate checkout or remote working directory.
* **Before** asking the user to run scripts, restart Quadlets, or execute code on `trader`:
  1. Commit and push from `lgram`:
     ```bash
     git add <files>
     git commit -m "..."
     git push origin main
     ```
  2. Instruct the user to pull on `trader`:
     ```bash
     cd ~/trader-core
     git pull
     ```

### C. Podman & Systemd Execution Target
* Podman commands (`podman build`, `podman run`), Quadlet placements (`/etc/containers/systemd/`), and `systemctl` commands belong exclusively on `trader`.
* Running `podman` inside the agent sandbox on `lgram` will fail with `lstat /run/user: no such file or directory` due to lack of cgroup namespaces.

## 3. Standard Remote Deployment Procedure

When deploying new code or services to `trader`:

### Step 1: Local Verification on `lgram`
```bash
# In /home/vineet/mnt/trader-core:
./.venv/bin/python -m pytest
git status
git add -A
git commit -m "feat/fix: description"
git push origin main
```

### Step 2: Deployment on `trader` (via SSH)
```bash
# Connect to the LXC container:
ssh vineet@trader

# Navigate to the repo and sync:
cd ~/trader-core
git pull

# Run the automated deployment runner:
sudo ./deploy/setup_and_deploy.sh

# Or manage individual services:
sudo systemctl restart trader-dashboard
sudo systemctl restart trader-engine
```

### Step 3: Health Checks from `trader`
```bash
# Check Dashboard on port 5000:
curl -s http://localhost:5000/api/status | jq .

# Check Orchestrator link to Ollama & Open-WebUI:
curl -s http://localhost:5000/api/orchestrator/status | jq .

# Check systemd container logs:
journalctl -u trader-dashboard -n 50 -f
journalctl -u trader-engine -n 50 -f
```

## 4. Quick Troubleshooting Cheatsheet

| Symptom | Root Cause | Solution |
| :--- | :--- | :--- |
| `sudo: ./deploy/setup_and_deploy.sh: command not found` | Command was run from `~` instead of inside `~/trader-core` | Run `cd ~/trader-core` first, or run `sudo ~/trader-core/deploy/setup_and_deploy.sh`. |
| Script missing or outdated on `trader` | Changes on `lgram` were not pushed, or `git pull` was not run on `trader` | Push on `lgram` (`git push origin main`), then run `git pull` on `trader`. |
| `lstat /run/user: no such file or directory` | Attempted `podman` inside sandbox on `lgram` | Execute `podman` directly on the host or inside the `trader` LXC container. |
| `Read-only file system` on `~/.config/containers` | Read-only mount in sandbox | Install Quadlets using rootful paths (`/etc/containers/systemd`) or directly on the LXC host. |
| Network unreachable to `10.10.10.15` or `192.168.2.15` | Sandbox isolation on laptop | Test and execute network connections directly on the `trader` LXC container. |
